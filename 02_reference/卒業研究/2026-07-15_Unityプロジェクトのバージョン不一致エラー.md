## Claude  _(2026-07-15 10:13)_

この「Enter Safe Mode?」は、Unityがプロジェクトを開いた際にコンパイルエラーを検知したときに出るダイアログです。GitHub経由でクローンした後によく出るパターンで、原因はだいたい決まっています。

## まずやること

**「Enter Safe Mode」を選んでください**（Ignoreは非推奨）。Safe Modeなら壊れた状態のままスクリプトが動くのを防ぎつつ、エラー内容を安全に確認できます。

Safe Modeに入ったら、`Window > General > Console` を開いて、具体的なエラーメッセージを確認してください。特に以下のようなエラーがないか見てください：
- `The type or namespace name 'XXX' could not be found`
- `Assembly 'XXX' not found`
- DLL/native pluginに関する警告

## こはくさんの構成で特に疑われる原因

MediaPipeUnityPlugin、Deform、Runtime OBJ Importer、Steam Audioという構成だと、以下が典型的な原因です：

**① 大きいバイナリファイルがGitHubに正しくpushされていない**
GitHubは1ファイル100MB超だとpushをブロックします（Git LFS未設定だと特に）。MediaPipeUnityPluginのネイティブモデルファイル（.bytes, .tflite等）やSteam Audioのネイティブライブラリ（.dll, .so）はこれに引っかかりやすいです。
→ 自宅PCで `git push` した際に警告やエラーが出ていなかったか確認してください。GitHubのリポジトリページで該当フォルダ（例: `Assets/MediaPipeUnity/...`, `Assets/Plugins/...`）を開き、ファイルが実際に存在するか確認するのが早いです。

**② .gitignoreが必要なフォルダまで除外している**
Unity標準の.gitignoreは `Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/` などを除外しますが、これは正常です（Unityが再生成するので問題なし）。ただし誤って `Assets/Plugins/` や特定のアセットフォルダまで除外設定に入っていないか確認してください。

**③ Asset Store有料アセット（Deform、Runtime OBJ Importer）がそもそもコミットされていない**
Asset Store経由で購入・ダウンロードしたアセットは、ライセンス上リポジトリに含めていない、または誤ってgitignoreされている可能性があります。この場合、クローン先PCでは該当クラスが存在せずコンパイルエラーになります。
→ 大学PCで同じAsset Storeアカウントにログインし、Deform・Runtime OBJ Importerを個別に再インストールする必要があるかもしれません。

**④ Unityのバージョンが完全一致していない**
「対応バージョン」が2022.3 LTS系だとしても、パッチバージョン（例: 2022.3.10f1 と 2022.3.45f1）が違うと、パッケージ依存関係でエラーが出ることがあります。
→ 自宅PCの `Unity Hub > プロジェクト` でバージョン番号を確認し、大学PCと完全一致させてください。

**⑤ Deform統合時に削除したasmdefの変更が正しくコミットされているか**
以前asmdefファイルを削除してassembly競合を解消した経緯があるので、その変更（削除自体）がgit上でも反映されているか確認してください。`git status` で該当ファイルが消えているか、GitHub上でも消えているかを見るのが確実です。

## 対応手順（自宅PCで作業）

**① `.gitignore` を確認**

自宅PCのプロジェクトルートで `.gitignore` を開き、以下のような記述がないか確認してください：

```
もしあれば、その行を削除（またはコメントアウト）してください。

**② Gitの追跡状況を確認**

```

```
を実行し、`OBJImport` フォルダが `Untracked files` に出てくるか確認してください。もし何も表示されない場合は、`.gitignore` 以外の原因（例えば `git rm --cached` 済みなど）も考えられます。

**③ 追加してコミット・push**

```

git add Assets/OBJImport.meta
git commit -m "Add missing OBJImport (Runtime OBJ Importer)"

※ `.meta` ファイルも一緒にpushしないと、大学PC側でUnityがGUIDを再生成してしまい、他のプレハブやシーンからの参照が壊れる可能性があるので注意してください。

```
git pull
```
Unityに戻り、一度エディタを閉じて再度開き直せば、Dummiesman名前空間が解決されるはずです。

## 補足：気になる点

もしこれが原因で一部ファイルが正しく同期・コミットできていなかった場合、今後も同様の「ファイルが実は存在しない/中身が空」という問題が起きる可能性があります。Unityプロジェクトは基本的に **OneDriveの同期対象外にする**（フォルダの同期を一時停止するか、対象から除外する）ことを強くおすすめします。GitでバージョンA管理している以上、OneDriveとの二重管理は競合の元になります。

## Claude  _(2026-07-15 10:51)_

このダイアログは、今回のDummiesmanエラーとは無関係です。プロジェクト内に含まれている「Fast Script Reload」というアセットが、Unityの「Auto Refresh」設定について確認してきているだけです。

## 何を聞かれているか

Unityの「Auto Refresh」がONの状態だと、Play Mode中にスクリプトを変更すると毎回フル再コンパイルが走ります。Fast Script Reloadはこれを高速化するアセットで、その恩恵を最大限受けるには「Auto Refresh」をOFFにして手動リフレッシュ（Ctrl+R）に切り替えることを推奨している、という内容です。

## 選択肢の意味

| ボタン | 内容 |
|---|---|
| Ok, disable asset auto refresh | Auto RefreshをOFFにする。以後スクリプト変更を反映するには手動で `Assets > Refresh`（Ctrl+R）が必要 |
| No, don't change | 今は変更しないが、次回também聞かれる |
| No, don't change (stop showing this message) | 変更せず、今後このダイアログを二度と出さない |

## 今回のおすすめ

今はDummiesmanのエラー解消中で、Fast Script Reloadの恩恵（Play Mode中の高速リロード）を積極的に使う場面ではないはずなので、

**「No, don't change (stop showing this message)」**

を選んで、設定は変えずにダイアログだけ消してしまうのが安全です。Auto RefreshをOFFにすると、後々「保存したのに反映されない」と混乱する原因になりやすいためです（手動リフレッシュを徹底する運用に慣れているなら、OFFにしても問題ありません）。

選んだ後、Package ManagerでのRuntime OBJ Importerインストール作業に戻って大丈夫です。進捗があれば教えてください。

## Claude  _(2026-07-15 11:17)_

良い質問です。結論から言うと、**GitHub Desktopは「フォルダの中身」を監視しているだけで、フォルダの場所自体に固定の制約はない**ので、正しい手順で移動すれば問題ありません。ただし何点か注意すべき順序があります。

## 移動前の注意点

### ① 未コミットの変更がないか確認する
GitHub Desktopを開き、変更一覧（Changes タブ）に何か残っていないか確認してください。もし残っていれば、移動前に一度コミットしておくと安全です（pushまでは不要、ローカルコミットでOK）。

### ② OneDriveのファイルが完全にダウンロード済みか確認する
OneDriveの「Files On-Demand」機能により、一部ファイルが実体を伴わない「クラウドのみ」状態（雲アイコン）になっている可能性があります。この状態のまま移動すると、実体のないファイルとしてコピーされる恐れがあります。

対処：エクスプローラーでプロジェクトフォルダを右クリック → **「このデバイス上で常に保持する」** を選択し、すべてのファイルを実体としてダウンロードさせてから作業してください（緑のチェックマークになるまで待つ）。

## 移動手順

### ③ Unity・GitHub Desktopを閉じる
Unity Editorを完全に終了してください。GitHub Desktopも念のため閉じておくと安全です（開いたままでも技術的には可能ですが、移動中に監視プロセスが中途半端な状態を検知することがあるため）。

### ④ 移動先フォルダを決める
OneDriveやGoogle Drive等の同期対象外の場所に、新しいフォルダを用意します。例：
```
C:\Projects\Virtual-Showcase-Kohaku
```
（Unity/Gitのプロジェクトは日本語パスや長いパス、特殊記号を避けるのが無難です）

### ⑤ フォルダごと移動する
エクスプローラーで、現在のプロジェクトフォルダ（`.git` フォルダを含む親フォルダ全体）を選択し、**切り取り→貼り付け**（またはドラッグ＆ドロップ）で移動先へ移してください。

- `.git` フォルダは隠しフォルダですが、フォルダごと移動すれば中身の隠しファイルも自動的に一緒に移動されます。表示設定を変えて個別に見る必要はありません。
- 「コピー→確認→元を削除」の順にしたい場合は、まずコピーし、移動先で `git status` が正常に表示されることを確認してから元フォルダを削除する方法でも安全です。

### ⑥ GitHub Desktopに新しい場所を教える
GitHub Desktopを開くと、おそらく以下のような警告が出ます：
> This repository has been moved or deleted...（または該当リポジトリがリストから見えなくなる）

この場合：
1. GitHub Desktop左上のリポジトリ一覧から該当リポジトリを選択
2. 「Locate...」ボタンが出ていればクリックし、新しいフォルダパスを指定
3. もし一覧から消えている場合は `File > Add local repository` から新しいパスを指定して再登録

これで、git履歴（コミット履歴、リモート設定含む）はすべてそのまま引き継がれます。**再クローンは不要です。**

### ⑦ Unity Hubにも新しい場所を教える
Unity Hubの「プロジェクト」一覧に古いパスのエントリが残るので：
1. 古いエントリの「…」メニューから「Remove」（プロジェクト自体は消えず、リストから外れるだけ）
2. 「開く」→「参照」から新しいフォルダ内の `.sln` ではなく、プロジェクトフォルダ自体（Assetsフォルダの親）を選択して追加

### ⑧ 動作確認
1. Unityでプロジェクトを開き、正常に起動するか（Safe Modeが出ないか)確認
2. GitHub Desktopで `git status` 相当の表示が移動前と一致しているか（変更が消えたり増えたりしていないか）確認
3. 試しに何かダミーの変更をしてコミット→pushが通るか確認

## まとめの順序

```
① 変更をコミット
② OneDriveでファイル実体化
③ Unity・GitHub Desktop終了
④ 移動先フォルダ作成
⑤ フォルダごと移動
⑥ GitHub Desktopに新パスを指定
⑦ Unity Hubに新パスを指定
⑧ 動作確認
```

この手順なら、git履歴もGitHub Desktopとの連携も失わずに安全に移行できます。作業中に不明な画面が出たら、その都度スクリーンショットを見せてください。

## Claude  _(2026-07-15 11:40)_

**「Virtual-Showcase-Kohaku」フォルダそのものを丸ごと移動**してください。中身だけを選択して移動するのはNGです。

## 理由

以前の画像2（GitHubリポジトリ）を見ると、リポジトリのルート直下に `models`, `scripts`, `src`, `.vscode` などが並んでいました。パンくずリストは `hirose > Virtual-Showcase-Kohaku > src > Assets` だったので、構造はこうなっています：

```
Virtual-Showcase-Kohaku/     ← ここに .git フォルダがある（リポジトリのルート）
├── .git/                    ← 隠しフォルダ（Gitの管理情報本体）
├── .vscode/
├── models/
├── scripts/
└── src/
    └── Assets/
        └── ...（Unityのプロジェクト本体）
```

つまり `.git` フォルダは `Virtual-Showcase-Kohaku` の直下にあります。ここで「中身だけ」を選んで移動してしまうと、`.git` フォルダ自体は移動されるものの、**移動先の親フォルダとの相対関係が変わってしまい**、GitHub Desktopが正しく認識できなくなる可能性があります。また、隠しフォルダである `.git` を「表示」設定なしで中身選択すると、うっかり選び漏らすリスクもあります。

## 具体的な操作

現在、恐らくこういう場所にあるはずです（前回の画像1より）：
```
（OneDrive同期フォルダ）\hirose\Virtual-Showcase-Kohaku
```

**① `hirose` フォルダを開く**（`Virtual-Showcase-Kohaku` の一つ上の階層）

**② `Virtual-Showcase-Kohaku` フォルダ自体を選択**（中に入らず、フォルダのアイコンをクリックして選択状態にする）

**③ 切り取り（Ctrl+X）**

**④ 移動先（例：`C:\Projects\`）に移動して貼り付け（Ctrl+V）**

結果として：
```
C:\Projects\Virtual-Showcase-Kohaku\
├── .git/
├── .vscode/
├── models/
├── scripts/
└── src/Assets/...
```

という、元と全く同じフォルダ構造がそのまま新しい場所に再現されます。これが最も安全で、GitHub DesktopもUnity Hubも「同じプロジェクトが場所を変えただけ」と認識しやすくなります。

移動が終わったら、前回お伝えした通り GitHub Desktop で「Locate...」して新しいパスを教えてあげてください。
