## 重要な発見:「Gemini v6」は存在しない

Ultraleap公式の世代呼称は以下の通りです。

- **Gemini = 第5世代**(v5.x系のみ。5.0.0 〜 5.20.0あたりまで)
- **Hyperion = 第6世代**(v6.x系。2024年6月リリース、Geminiの後継)

つまり資料内の「Gemini v6」は、正式には**Hyperion v6**です。これは単なる呼び方の違いではなく、UltraleapがLeap Motion Controller 2のユーザーには第6世代のHyperionを、それ以外は第5世代のGeminiを使うよう公式に案内している、という点が重要です。つまり**初代Leap Motion Controller(このプロジェクトで使用中の機材)は、そもそもHyperion向けに設計されていない**可能性が高いです。

さらに、この症状と一致するユーザー報告も見つかりました。あるフォーラムで、Hyperion 6.2はIntel Mac環境で非常にパフォーマンスが悪いのに対し、旧バージョンのGemini 5.2は問題なく動作するという報告があり、貴プロジェクトの「v6=7fpsまで低下」という症状と一致します。これは貴プロジェクト固有のバグではなく、初代Leap Motion Controller + Hyperionという組み合わせに起因する既知の相性問題である可能性が高いです。

## Unity Plugin側も「Hyperion前提」になっている

さらに調査すると、Unity Plugin v7.x系はドキュメント上「Gemini V5.2以上」を要求すると書かれてはいるものの、実際のリリースノートでは**テスト済みTracking Clientバージョンが明記**されています。

- Unity Plugin **7.0.0 / 7.2.0**:テスト対象は Tracking Client Windows **v6.0.0 / v6.1.0(Hyperion)**
- 一方、Unity Plugin **6.14.0**:テスト対象は Tracking Client Windows **v5.17.1**(Gemini世代最後期の安定版)

つまり「v7.3.0はGemini5.2以上で動くはず」という記述は最低要件であって、**実際にv7.3.0が動作確認されているのはHyperion(v6系)**です。これがGemini v5.0.0との接続失敗の直接原因と考えられます。

## 推奨する組み合わせ(方針Aと方針Bの統合案)

方針Bで探していた「中間バージョン」ではなく、**Gemini世代の中で完結させ、Unity Plugin側もそれに合わせて古いものに戻す**方が理にかなっています。

| 項目 | 推奨バージョン | 根拠 |
|---|---|---|
| Tracking Service | **Gemini v5.17.1 または v5.20.0** | 初代Leap Motion Controller向けの推奨ドライバとして明記されているGemini最終安定版 |
| Unity Plugin | **v6.14.0** | 公式にTracking Client v5.17.1でテスト済み。Unity 2022.3系対応も明記 |

これなら「要件は満たすが未検証のつぎはぎ」ではなく、Ultraleapが実際にテストした組み合わせになります。

- 資料にある通り「`.meta`ファイルも必ずセットで」という原則はここでも同じです。フォルダ削除ならUnity/Explorerどちらで消しても`.meta`も一緒に消えるので問題ありません
- `TouchPushDeformer.cs` や `FrogTouchController.cs` など、Leap Motion SDKに依存していない自作スクリプトは影響を受けませんが、削除後に一度Unityを開いてコンパイルエラーが出ないか確認してください(LeapProviderなどSDK型を直接参照している箇所があれば、インポート完了までエラーが出るのは正常です)
- Gitで管理しているので、削除自体もコミットしておくと「削除」と「新バージョン追加」の差分が分かりやすくなります

削除が終わったら、前回お伝えしたUnity Plugin 6.14.0のリリースページから `.unitypackage` をダウンロードし、Package Manager「Add package from disk」または通常のCustom Package importでインポートしてください。

## Claude  _(2026-07-17 12:36)_

この現象は、**Unity Pluginの入れ替えは完了しているが、PC側のTracking Service(Ultraleap本体のドライバ)がまだGemini v5.17.1に切り替わっていない**ために起きている可能性が高いです。

## 何が起きているか

エラーの発生源は `LeapServiceProvider.OnDrawGizmos()` です。これはScene ViewでUnityが**毎フレーム自動的に呼び出す**処理で、内部で「接続されているデバイスの種類を検出する」というネイティブ関数(`ServerStatus.GetStatus`)を呼んでいます。

このネイティブ呼び出しがnull(不正なポインタ)を返してきており、それをC#側でマーシャリングしようとして例外が発生 → 毎フレーム(Scene Viewが再描画されるたび)同じ例外が繰り返し発生 → Unityが「コード実行待ち」でフリーズ気味になる、という流れです。

これは典型的に、**Tracking Serviceが正しく起動していない/期待するバージョンと噛み合っていない**ときに起きます。具体的には以下のいずれかが疑われます。

1. PC側にまだHyperion(v6)が入ったままで、Gemini v5.17.1をまだインストールしていない
2. Tracking Serviceが全く起動していない(サービスがクラッシュ/未起動)
3. HyperionとGeminiが競合した状態(前回お伝えした通り、この2つは同じインストール先を使うため**共存できず、片方が片方を上書きする**仕様です)

## まず確認してほしいこと

**Q: Gemini v5.17.1のTracking Serviceのインストールはもう済んでいますか?** それとも、まだUnity Plugin側の入れ替えだけで、PC側のドライバ入れ替えはこれからですか?

もしまだであれば、それが今回のクラッシュの直接原因です。先にPC側のドライバをGemini v5.17.1に入れ替える必要があります。

## 今すぐフリーズを止める方法

作業を続ける前に、この繰り返しエラーを止めてください。

1. Unityが完全に固まっている場合は、タスクマネージャーで強制終了もやむを得ません
2. 応答する場合は、Scene View右上のGizmosボタン(目のアイコン横のドロップダウン)を**オフ**にして、OnDrawGizmosの呼び出し自体を止めてください
3. それでも直らない場合は、`LeapServiceProvider` がアタッチされているGameObjectを一時的に無効化(非アクティブ化)してから作業を続けてください

## なぜv5.0.0だとまずいのか

v5.0.0は**Gemini初期のdeveloper preview版**で、正式なV5.2+要件が確立される前のバージョンです。Unity Plugin側のドキュメントでも「V5.2以上」が最低要件として明記されており、v5.0.0はこの最低要件すら満たしていません。さらに、今回入れたUnity Plugin 6.14.0は公式に **v5.17.1** でテスト済みと明記されています。v5.0.0とv5.17.1の間ではLeapC.dll側のAPI(`ServerStatus`まわりを含む)にも差分がある可能性が高く、今出ている`NullReferenceException`(`ServerStatus.GetStatus`が不正な値を返す)は、まさに**Tracking Service側が古すぎてUnity Plugin側が期待するAPIに応答できていない**症状と一致します。

実は資料にも「v5.0.0 + Unity Plugin v7.3.0 → 接続できない」という記録が既にありました。今回はUnity Plugin側を下げたことで"接続はできるがクラッシュする"という一歩進んだ状態になった、と見るのが妥当です。

## 対応

v5.0.0をアンインストールし、v5.17.1に入れ替えることをお勧めします。

**入手方法**: 公式サイトから削除されているため、Internet Archiveにコミュニティがバックアップしたドライバ集があります。

- https://archive.org/details/Leapmotion-drivers

この中に「Leap Motion v1」向けの **Gemini Driver v5.20.0**、および「Ultraleap Gemini v5.17.1」が含まれています。どちらもUnity Plugin 6.14.0のテスト対象範囲(V5.17.1〜)に収まるはずです。

⚠️ 一点注意:これは非公式のアーカイブです。研究室のPCで実行する前に、指導教員やIT管理者のポリシーに従って問題ないか確認してから進めてください(大学PCということなので、勝手にインストーラーを実行してよいか念のため確認をお勧めします)。もし社内ポリシー上難しければ、Web Archive(web.archive.org)経由でUltraleap公式サイトの旧ダウンロードページ自体をキャッシュから探す方法もあります。

2. PC再起動
3. v5.20.0(またはv5.17.1)をインストール

5. タスクトレイのUltraleapアイコンが緑になるか確認
