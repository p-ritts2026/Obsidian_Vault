# ネタ見せちゃんフォーム作成アプリ 構成まとめ

> 元の会話ログ（[[02_reference/サークル活動/2026-06-29_お笑いサークル向けネタ見せフォーム作成アプリ.md]]）は96往復あって長いので、
> 「今どういうアプリで、何ができて、どこに注意が必要か」だけをここにまとめました。
> コードの詳細を見たいときだけ元ログを参照すればOKです。

## 1. これは何のアプリ？

お笑いサークルの「ネタ見せ」ライブ後に配るGoogleフォーム（感想・アドバイス募集用）を、
毎回手作業で作る代わりに **ボタン1つで自動生成する** ツール。

- 開催日・説明文・出演者（名前＋YouTubeリンク）を入力
- 「フォームを作成」を押すと、その場で本物のGoogleフォームが新規作成される
- 出来上がったフォームは自動でDrive内「ネタ見せちゃん」フォルダに整理される
- LINEでそのままシェアできる告知文も自動生成される

## 2. 技術構成

**Google Apps Script（GAS）のWebアプリ**として動いている。ファイルは2つだけ。

| ファイル | 役割 |
|---|---|
| `Code.gs` | サーバー側ロジック。フォーム作成・Drive操作・YouTube再生リスト取得など |
| `index.html` | 画面（入力フォーム・結果表示） |

- `doGet()` が入り口で、`index.html` をWebページとして返す
- 画面からのボタン操作は `google.script.run` 経由で `Code.gs` の関数を呼ぶ
- 素のHTMLファイルを手元で開くだけでは動かない（Googleの権限の下で実行する必要があるため）

**デプロイ設定**
- 実行するユーザー：**ウェブアプリにアクセスしているユーザー**（＝各担当者自身のGoogleアカウントで実行される）
- アクセスできるユーザー：**Googleアカウントを持つ全員**（実質はURLを知っている数人の担当者だけが使う運用）
- この設定のため、**出来上がったフォーム・保存フォルダ・前回リストなどは「作った人自身のGoogleアカウント」側に作られる**（他人のDriveに紛れ込まない）

## 3. 主な機能

- **出演者リストの入力**
  - 1組ずつ手入力
  - スプレッドシートなどからの「名前＋URL」一括貼り付け
  - YouTube**再生リストのURL**を貼るだけで、中の動画を全部まとめて取り込み（YouTube Data API使用）
  - 名前はYouTubeの動画タイトルから自動取得（手直しも可）
- **フォーム自動作成**
  - 各出演者ごとに「動画（VideoItem）」＋「コメント記入欄」の2枠を自動生成
  - 名前にリンクを埋め込む1枠形式は**Forms APIの仕様上不可**（手動編集でしかできない機能のため）
- **説明文の自動調整**：開催日を入れると「○月ライブのネタ見せ」の月が**開催日の翌月**に自動計算される（手で書き換えていた場合は上書きしない）
- **保存先の自動整理**：作成したフォームはDrive内「ネタ見せちゃん」フォルダへ自動移動
- **LINE告知文の自動生成**：フォーム作成完了後、「【フォーム】＋回答用URL／【再生リスト】＋再生リストURL」というLINE貼り付け用の文面をワンボタンでコピー可能
- **前回入力の呼び出し**：以前は自動復元だったが、「開くたびに前回データが残る」のを避けるため、**ボタンを押したときだけ**前回の出演者リストを呼び出す仕様に変更済み

## 4. 権限まわりの仕組み（重要）

このアプリは「フォーム作成」「Driveのフォルダ操作」「YouTubeデータの読み取り」という3種類の権限を使う。
Googleの仕様上、**新しい種類の操作を初めて使うときだけ、使う本人が1回手動で許可する**必要がある。

- 許可用の関数は `authorizeAll` に一本化済み（Drive・YouTubeなどをまとめて許可）
- 使う人が増えても、その人が初回に `authorizeAll` を実行→許可すればOK
- 新機能追加時にこちらで対応が必要な場合は、`authorizeAll` に1行追記するだけで済む設計

## 5. 既知の注意点・トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 「ファイルを開くことができません」 | ブラウザに複数のGoogleアカウントが同時ログインしている（GAS Webアプリの仕様上の制約） | シークレットウィンドウで目的のアカウントだけログインする／普段のブラウザから他アカウントをログアウトする |
| LINEやInstagram内で開くとログインできない | アプリ内蔵の簡易ブラウザはGoogleログインを弾く仕様 | リンクを「ブラウザで開く」からSafari/Chromeへ渡す |
| 動画のサムネイルが縦長・黒帯が出る | Googleフォームの動画項目（VideoItem）自体の表示仕様（API側で縦横比を直接指定する手段がない） | `setWidth`で表示幅を調整（現在320px）以外の根本解決策なし。仕様として受容 |
| フォームのURLが`forms.gle`の短縮形にならない | 短縮URLは手動の「送信」ボタンから発行するものでAPI取得不可 | 長いURL（`docs.google.com/forms/...`）をそのまま使う。リンクとしての機能は同じ |
| `youtube.playlistItems.list を呼び出す権限がありません` | YouTube読み取り権限がまだ許可されていない（初回）、または後述のOAuthテストモード特有の再失効 | `authorizeAll`を実行して許可し直す。恒久対策は次項 |

## 6. 対応済み：再生リスト権限エラーの恒久対策（2026-07-30 解決）

**症状**：再生リスト取り込みで`youtube.playlistItems.list を呼び出す権限がありません`が数日〜十数日おきに再発していた。

**原因**：Google CloudのOAuth同意画面が「テスト」ステータスのままだと、付与された権限（リフレッシュトークン）は**7日間使われないと自動的に失効**する仕様があるため。

**対応した内容（すべて無料でできる範囲）**
1. Google Cloud Consoleで新規プロジェクトを作成し、Apps Scriptの「プロジェクトの設定」から紐づけ先をデフォルトプロジェクト→この新プロジェクトに変更
2. 新プロジェクトのAPIライブラリで「YouTube Data API v3」「Google Drive API」を手動で有効化
   - デフォルトプロジェクトでは自動的に有効化されていたが、標準（ユーザー作成）プロジェクトでは個別に有効化が必要だった
3. OAuth同意画面（新UIでは「Google Auth Platform」→「Audience」タブ）で、公開ステータスを「テスト」→「本番環境」に変更
4. `authorizeAll`関数を再実行し、Drive・YouTubeの権限を許可し直し
5. 実行ログで`OK（Drive）`・`OK（YouTube）`の両方を確認 → 完了

**結果**：本番環境に公開したことで7日失効の制約がなくなったため、今後は今回のような定期的な再認可は不要になる見込み。
